System Architecture & Viva Presentation Reference

Frontend Tier

HTML5 + CSS3 + Vanilla JS (ES6+)

Responsive layouts, DOM manipulation via fetch() API, real-time reactive requisition preview, modal components, and client-side form validations.

Application Tier

Node.js + Express.js

RESTful API routing, JSON body parsing, CORS middleware, JWT authentication with bcrypt password hashing, and centralized error handling middleware.

Database Tier

MongoDB + Mongoose ODM

Schema definitions (Donor, BloodRequest, User), enum constraints, compound indexes (bloodGroup + city), and auto-seeding data repository.

quiz Top 5 End-Semester Viva Questions

Q1: How does the client communicate with the backend?

The client uses the asynchronous fetch() API to make HTTP requests (GET, POST, PATCH, DELETE) to Express REST routes, passing JSON payloads in request headers and receiving JSON responses.

Q2: Why use Mongoose instead of the native MongoDB driver?

Mongoose provides schema validation (required fields, enum values like valid blood groups, age range 18-65), pre-save middleware hooks (such as bcrypt password hashing), and indexed query optimization.

Q3: How is donor availability updated without page reloading?

Clicking the availability toggle fires a PATCH /api/donors/:id/availability request. The server modifies the boolean flag in MongoDB, responds with status 200, and JavaScript dynamically updates the DOM element and KPI counter.

Q4: How is password security implemented?

Passwords are never saved in plain text. A 10-round salt is generated via bcryptjs, hashing the password before saving to the database. Verification during login compares the bcrypt hash.
